## Grid idea thread (2026-11-01)

The pitch (author not labeled, and Camille's replies suggest it was Camille):

- Public data exists (ERCOT, utility outage maps, HHS data on people with medical equipment, census, weather), but it is not centralized.
  None of it shows in real time which specific houses lost power or how cold they are getting.
- The hardware fills that gap: a small box that plugs into a wall outlet, with a battery and temperature sensor.
- When power goes out, the box switches to battery and reports to the team's website.
- The website shows a live map of which houses are out, for how long, and how fast each one is getting cold.
- That data combines with public vulnerability data to rank which homes need a welfare check first.
- Hardware stays simple (ESP32, battery, temperature sensor, 3D-printed case), so most of the time goes to the map and simulation.
- There is room for a user-facing app that logs the info and marks shelters.

Connectivity concern (speaker not labeled): how does the box report if the wifi is gone?
The same speaker asked whether it could be a black box for a house.

Camille's answers:

- The box connects to the phone app over Bluetooth, and the app sends the data over cellular.
- Boxes talk to each other with ESP-NOW, so a box with no internet passes its message to a neighbor's box that still has internet.
- If nothing is reachable, the box saves the data and uploads it after it reconnects.

Matt said these were good points.

Hardware debate:

- Matt suggested a Raspberry Pi instead of an ESP32, because Matt has a range extender antenna that looks great and Linux is more flexible for network management.
- Camille suggested using the Pi as the gateway, like a main hub at a fire station that stays plugged in, with the antenna collecting from all the house boxes.
  The house boxes would stay ESP32 because they use less battery in an outage, and a Pi's SD card can corrupt when power cuts suddenly.
  Camille was unsure about this.
- No one confirmed this split in the paste.
