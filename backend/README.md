# Backend

Every backend part talks to one SpacetimeDB database.
Maincloud: `STDB_URI=https://maincloud.spacetimedb.com`, `STDB_DATABASE=assess-0hw81` (dashboard https://spacetimedb.com/assess-0hw81).
Local fallback: `spacetime start --listen-addr 0.0.0.0:3000`, then `STDB_URI=ws://<laptop-a-ip>:3000` with the same database name.
Each part reads these from its own git-ignored `.env`; copy its `.env.example` first.
Names, tables, and reducers are in `docs/specs/CONTRACTS.md`.

## `spacetimedb/` - the module

Spec: `docs/specs/spacetimedb.md`.

```bash
cd backend/spacetimedb
npx tsc --noEmit -p . && spacetime build   # typecheck and build
npm test                                   # smoke suite on an in-memory server at 127.0.0.1:3917
npm run publish:local                      # publish assess-0hw81 to the local server
npm run publish:cloud                      # publish assess-0hw81 to Maincloud
npm run generate                           # regenerate ../spacetimedb-bindings, then commit it
```

A breaking schema change needs `--delete-data=always` on publish, which wipes the data; warn the team first.

## `spacetimedb-bindings/`

Generated by `npm run generate` in `spacetimedb/`.
Do not edit by hand, and import from here instead of running `spacetime generate` yourself.

## `sim/` - demo simulator

Spec: `docs/specs/demo.md`.
`.env`: `STDB_URI`, `STDB_DATABASE=assess-0hw81`, and optionally `STDB_TOKEN`, `MEDIA_BASE`, `PERCEPTION_BASE`, `GLASSES_BASE`.

```bash
cd backend/sim
npm run sim -- help              # every command and its short form
npm run sim -- setup             # create the demo site, cells, and sim actors
npm run sim -- console           # interactive controls
npm run sim -- timeline demo     # the judged demo (hard-coded, 2026-11-08)
npm run sim -- scene             # seed an in-progress board (searched houses, survivors, house 4 report), start rescuers and sim-dog
npm run sim -- search house 3    # short: sr; queue a sim-dog search mission for one house
npm run sim -- timeline judge    # run a timeline (demo, scene, e2e, judge, video, stress); add --dry to print it
npm run reset                    # republish with --delete-data=always, then setup (never on Maincloud during judging)
npm test && npx tsc --noEmit
```

### Run the demo

The judged demo is hard-coded (decision 2026-11-08): only SpacetimeDB runs live, and the sim scripts the robot (`sim-dog`), the find, the breathing result and score, and rescuer actions.
Set `STDB_URI=https://maincloud.spacetimedb.com` and `STDB_DATABASE=assess-0hw81` (or the local fallback), then run `npm run sim -- setup` and `npm run sim -- timeline demo`.
`timelines/demo.json` starts a run, arms the hidden survivors, starts `sim-dog`, queues `search house 3`, waits for the house 3 survivor (fallback `robot replay house3`), and ends the run when you press Enter.
Before judging, republish Maincloud clean from the repo root with `spacetime publish assess-0hw81 -p backend/spacetimedb --server maincloud --delete-data=always --yes`, then run `setup`.
The `judge`, `e2e`, `video`, and `stress` timelines remain as rehearsal and video material.
Details: `docs/specs/demo.md`, "Judged demo (hard-coded, 2026-11-08)".

## `glasses-service/` - glasses backend

Spec: `docs/specs/glasses.md` section 5.
`.env`: `STDB_URI`, `STDB_DATABASE=assess-0hw81`, `PORT=8787`, `TILE_SOURCE`; set `FAKE_DB=1` to run on fixture data with no database.
The default rescuer is `cayden` (`rescuers.json`).

```bash
cd backend/glasses-service
npm run tiles                    # prefetch map tiles for the site (needs internet)
npm run dev                      # 0.0.0.0:8787: /glasses, /view, /phone, /healthz
npm test && npx tsc --noEmit
```
